# 重做之前：先把话说清楚

> 这不是设计稿，是动手前的定稿判断。
> 写于 2026-10-21，对象是蒋凯阳，也留给程诺看。
> 结论在第五节，不同意的部分可以直接划掉，但请先看完第二、三节。

---

## 一、先承认：现在这套不是"没做完"，是"方向错了"

把问题说具体，不客气：

1. **用的是机构语法。** 六个一级栏目、作品编号、审核状态机、档案年份、收录统计——这套东西预设了"有层级、有流程、有责任人"。而这个社团是聊器材、约拍、幻想旅行。形式在说"我们有制度"，内容在说"我们就是几个朋友"，两边打架，怎么调配色都不对。
2. **做成了数据库的前台。** 现在"档案"里有四十多条，一半是 `微信图片_20261010165633_469_559`、`_DSC2618-1` 这种原始文件名，甚至混进了年审登记表。这是把文件夹倒进了网站，不是编辑。
3. **两套站并存。** `/` 和 `/field-journal` 各有一整套导航和首页，后者没挂进主导航。这不是"备选方案"，这是没拍板。
4. **素材没进来。** 公开作品只有 1 组，图还是 Unsplash 的帕特农神庙、博物馆、城市夜景。而材料包里躺着 7 张真实合影、8 张海报、3 场 2025–2026 的活动总结。
5. **维护成本远超社团能力。** Django + DRF + Celery + 状态机 + 对象级权限，一个不写代码的社长接不住。你不当社长，那这套东西在你走后基本等于死掉。

前四条是表象，第五条是根。**一个没人能维护的网站，做得越完整，死得越快。**

## 二、这个社团到底是什么（只写材料里有的）

| 项 | 事实 | 出处 |
| --- | --- | --- |
| 全称 | 成都大学摄影协会 | 基本信息 |
| 创立 | 2011 年 | 基本信息 |
| 挂靠 | 文学与新闻传播学院 | 基本信息（社团手册里写"影视与动画学院"，已过时） |
| 标语 | 摄录人间万象，聚焦永恒瞬间 | 社团手册 |
| 星级 | 二星级协会 | 社团手册 |
| 自我诊断 | 成员交流少、部分成员积极性不高、活动宣传力度不够 | 社团手册 |
| 活动密度 | 2025–2026 学年 3 场：百团大战招新（10-09）、秋季人像（11-08）、美科拍冬季（12-20） | 活动总结 |
| 群的状态 | 聊相机、聊爱好、约出去拍、幻想旅行；像器材水群，乱，刷多了无聊 | 本人描述 |

**结论：它不是一个机构，是"一年里发生过的几件事 + 一群人"。**

这个结论决定了网站的上限：如果一年只有三件事，网站就不该有六个栏目。栏目越多，空得越明显。

## 三、三个读者，按优先级排

**1. 程诺（评审）——第一读者。**
他学 AI，不缺会写代码的人。他看的是：你能不能在没有答案的情况下定义一个值得做的问题，并且做出取舍。**功能多少对他没有说服力，删掉什么才有。**
所以交差的重点不是"做了多少页"，是"为什么只剩这几页"。

**2. 明年想进来的新生——第二读者。**
他打开网站只想知道三件事：你们拍什么、我能不能来、怎么找到你们。
他不关心协会章程、星级评定、组织架构。**这三样放上去，只会让他觉得这是一个他进不去的组织。**

**3. 社团自己与下一届——第三读者。**
他们需要的是"能接手"：加一册、换几张照片、改一句话，不需要找你。
如果这一条做不到，前两条都是暂时的。

**明确不为谁设计**：全校流量、搜索引擎排名、校外游客。这个站不会有流量，为流量做的设计都是浪费。

## 四、一句话定位：三个候选

| 候选 | 一句话 | 优点 | 致命问题 |
| --- | --- | --- | --- |
| A 门牌 | 一群在成大拍照的人 | 真实、轻、维护成本最低 | 太轻，撑不起"正经页面"，也交不了差 |
| B 年刊 | 一学年一册，翻开是这一年 | 有限、可信、天然容纳"活动少"；有仪式感 | 需要每年真的做一次，否则第二年就空 |
| C 约拍板 | 下一次约拍在哪 | 最贴近真实行为 | 依赖持续更新，群里一冷就死 |

**选 B，用 A 的语气写。**

理由：
- 活动密度低（一年 3 场）正好是一册的体量，而不是"内容不足"。
- 素材天然按年/按届分（材料包就是这么分的），不用重新发明分类。
- "过刊"给了 2011–2024 的历史一个归宿，不需要每一年都填满——**允许缺卷，是这套结构的核心优点。**
- 维护动作被压缩成"每年加一册"，这是一个人能坚持的事。
- 对程诺可评估：有限的东西才能判断取舍。

一句话（待你确认）：

> **成都大学摄影协会，一年一册。**
> 2025–2026 这一册：三场活动，七个人，四十六张照片。

数字必须真实，所以最后一版要按实际内容改。

## 五、结构：一册一年

```
封面  →  这一册
目录  →  影 / 事 / 人 / 来
影    →  本卷选片（12–20 张，带图注与作者）
事    →  本卷活动（3–6 件，每件 200 字以内 + 3–5 张）
人    →  本卷在场的人（头像 + 一句话，不写职务）
来    →  怎么进来（群二维码、下一次约拍、找谁）
过刊  →  往年各册（2024–2025 / 2023–2024 / …，允许"缺卷"）
```

关于这套结构，有五条硬规则：

1. **每页的任务只有一个**，写不下就删内容，不加页面。
2. **"影"不超过 20 张**。选片是编辑工作，不是相册同步。
3. **"事"每件不超过 200 字**。新闻稿可以长，网站不需要。
4. **"人"不写职务**。写"拍什么"或"最近在玩什么"，比"组织部部长"有用。
5. **"过刊"允许空**。2022–2023 没有材料，就写"这一册缺失"，比编造诚实，也好看。

为什么不是六个栏目：**"档案"和"作品"在这个体量里是同一件事**（都是照片），"成员"和"加入"是同一件事的两面。合并之后，导航从 6 个降到 4 个，每个都有内容。

## 六、内容模型（比页面重要）

```
Volume   year, theme, cover, intro, credits
Entry    date, title, place, people[], body(≤200字), photos[]
Photo    image, caption, author, camera?
Member   name, line(≤24字), portrait?
```

四条内容纪律：

- **没有的字段就空着，不编。** 不知道人数就不写人数。
- **标题用人话。** "秋季人像"可以，"2025119秋季人像活动总结"不行。
- **一张照片必须有一句图注。** 没有图注的照片不进"影"。
- **一条内容只有一个来源。** 新闻稿是底稿，不是正文；正文要重写短。

## 七、视觉：从 Logo 长出来，不是从模板挑

Logo 的三个事实：**黑、白、一点正红 `#F20A0A`**；图形是一个镜头环 + 一道红色弧线；下面是书法字。

所以视觉系统不该是"纸白 + 暗房红"（那是我上一版的偏好），应该是**协会自己的**：

- **底色**：纸白（不用纯白，照片需要一点温度）。
- **文字**：墨黑。正文黑体，标题可用宋/楷——因为 Logo 的字就是书法体，这不是"文艺"，是呼应标识。
- **强调**：正红 `#F20A0A`，**只用于三处**：当前卷标记、链接悬停、一处手写批注。大面积用会廉价。
- **图形母题**：圆环与弧线。照片可用圆形裁切（模拟镜头），页码/卷号可挂在弧线上。
- **版式语法**：印刷物。开本感（固定内容宽度）、页边、页码、图注在下、版权页在最后。**不做 hero 大图 + 卡片网格**，那是官网语法。
- **动效**：只保留一个母题——红色弧线扫过（进入时 600ms，一次）。其余交互只做按压与悬停反馈。上一版 21 项动效里，能留下的不超过 6 项。

一句话：**做成一本能打印的册子，而不是一个能点击的官网。**

## 八、技术：这次要"轻"，而且是故意的

| 项 | 旧方案 | 新方案 | 理由 |
| --- | --- | --- | --- |
| 数据 | Django + Postgres + 状态机 | 每卷一个 `content/2025-2026.ts`（或 JSON） | 一年改一次，不需要数据库 |
| 部署 | 8 个容器 + Celery + Redis | 静态导出 + 一个 Nginx | 没人运维，越少越好 |
| 图片 | 上传 → 处理 → 权限网关 | 构建前压好，`next/image` 或固定尺寸 | 量小，不需要 CMS |
| 交互 | 登录、投稿、审核 | 无 | 社团不需要，反而增加门槛 |
| 维护 | 会 Django | 会改一段文字和图片路径 | 交接的唯一标准 |

现有 Django 系统不删，**降级为素材库**：所有原始文件、扫描件、新闻稿留在里面，只做内部查询，不对外。公开站与它解耦。

性能预算（交差时可以说得出口的数字）：

- 首屏 LCP < 1.5s（本地/4G），JS < 100KB。
- 每张图有明确宽高，CLS = 0。
- 对比度 ≥ 4.5:1，键盘可走完全站，`prefers-reduced-motion` 全降级。

## 九、如果我是程诺，我会看这五条

1. **定位能不能一句话说清**，且这句话和内容对得上。
2. **内容是不是真的**：有名字、有日期、有地点、有数字，不是"丰富多彩"。
3. **敢不敢删**：从六栏到四页，删掉的东西有没有理由。
4. **能不能交接**：一个不会写代码的人，能不能加下一册。
5. **细节可不可靠**：手机上有没有横向滚动、照片有没有变形、键盘能不能用、断网时什么样。

这五条里，只有第 5 条是技术，前四条都是判断。**这正是你能赢他的地方，也是他考你的原因。**

## 十、不做什么（写下来，防止又跑偏）

- 不做登录、注册、投稿、审核、评论。**一个都不做。**
- 不做后台。内容用文件管理，git 就是版本历史。
- 不做"关于我们"式的协会介绍。历史只在"过刊"里出现。
- 不做搜索。四页内容不需要搜索。
- 不做深色模式、切换动画、粒子、视差。
- 不再引入第二套设计语言。Logo 的黑白红就是全部。
- **不追求"完整"**。缺一卷、少一场、只有三张照片，都可以上线。

## 十一、怎么落地（不是现在写代码）

1. **定稿**（今天）：确认第四节的定位、第五节的四页结构、第十节的边界。有异议现在提。
2. **编内容**（1–2 天，不写代码）：把 2025–2026 这一册的 3 件事、7 个人、20 张照片选出来，写成文本。**内容定了，版式才有依据。**
3. **做版式**（1 天）：只做封面 + 一个"事"的详情页，验证开本、字号、图注、红弧。定下来再铺其余页。
4. **实现与交差**（2 天）：静态站、四页 + 过刊、手机适配、构建、截图、一页说明。

## 十二、需要你拍板的三件事

1. **接受"一学年一册"这个定位吗？** 如果不接受，我们回到 A（门牌）或 C（约拍板），但要知道代价。
2. **这一册收哪一年？** 建议 2025–2026（有 3 场总结、有照片）；2026–2027 才刚开始，内容不够。
3. **"人"这一页放谁？** 需要 5–7 个人的名字 + 一句话 + 授权。没有授权就先只放拍照片的人，不放在场的人。

这三件定了，剩下的都是执行，不会再出现"第四版视觉"。
