# 从 Ultra 战队官网，到摄影协会官网

> 参照对象：`rmultra.cn`（成都大学 Ultra 战队，Vue + PrimeVue，预渲染）。
> 本文记录：它为什么"看着舒服"，哪三点能搬，哪三点不能搬，以及据此做的可点原型。
> 原型入口：`design/prototype/index.html`。静态 HTML，不进生产，不改现有前后端。

---

## 一、它真正值得学的，不是视觉

抓完它全部 8 个栏目（首页 / 站点导航 / 机器人 / 团队成员 / 拾光 / 留言墙 / 战队历程 / 加入我们 / 常见问题）后，结论是：

**1. 主体唯一。**
首页第一屏只有一句话 + 战队简介；紧接着是"机器人阵容"——英雄、工程、步兵、空中、哨兵、飞镖、雷达，每台机器带 3 个赛区排名指标。整个站只有"战队"一个主角，其余栏目都是它的侧面：人、历史、影像、工具、招新。

**2. 深浅分层。**
首页给外部看：一句话、阵容、招新。硬核数据在 `/robot`：赛季切换（2026/2025/2024）、赛区能力雷达、8 个维度的排名尺、每项都有赛区平均值、最高值和样本量（32 支队伍）。同一实体，两种读法，不是两个站。

**3. 规范感来自"可核对"。**
它没有用装饰证明自己专业。每个数字都有单位、对照基准、样本量和时间范围。"局均伤害 441.1，赛区平均 669.15，样本 32"——这句话本身就是可信度。视觉上只是白底、细线、等宽数字、克制的青蓝，把注意力全留给数据。

**视觉上"舒服"的原因**（可直接核对的 token）：内容宽 1280，头部 68，圆角 6/14/22，白底 + `#e4e8eb` 细线 + `#111820` 墨色 + `#087f9f` 青蓝，Inter + 系统中文。没有渐变、没有阴影堆叠、没有装饰插画。

## 二、它的三个缺点，正好是我们最容易复制的坑

| 你观察到的现象 | 在它站上的具体表现 | 我们的对策 |
| --- | --- | --- |
| 互动界面杂乱、重复 | `/sites` 是一个"导航的导航"，和主导航重复；`/message` 留言墙空着也占一级入口；成员卡里姓名出现两遍（桌面/移动双写）；机器人卡片的数据与 `/robot` 表格重复 | 不做"站点导航"，不做独立留言墙；讨论只挂在作品/活动下；成员信息单一来源；列表只给结论，细节只在详情 |
| 缺历史文件归档 | 只有"拾光"影像时间轴，没有可检索的策划、名单、教程、交接文档 | **档案做成一等栏目**：年份 + 类别 + 版本 + 权限，允许"待归档"空白 |
| 部分栏目套娃 | `/sites` 是导航的导航；`/robot` 是 赛季 → 赛区 → 机器人 → 指标 四层；成员是 团队 → 组 → 人 | 层级最多三层，常态两层：**列表 → 详情**；"关于"不单独成页 |

第三条最关键。它现在的 `关于` 页同时塞了协会介绍、成员墙、招新说明、FAQ——这正是"套娃"的起点：一个页面承担四种职责，用户永远不知道自己在第几层。

## 三、栏目映射

| Ultra 战队 | 摄影协会 | 数据来源 | 深度层 |
| --- | --- | --- | --- |
| 首页（简介 + 阵容） | **首页**：一句话 + 4 个真实数字 + 本期印样 | 数据库实时统计 | — |
| 机器人阵容 | **作品**：一组照片 = 一个作品系列 | Collection + Photo | 作品详情（大图/图注/参数/关联活动） |
| 团队成员 | **成员**：姓名、组别、届别、一句话、作品数 | Profile | 成员主页（本人填写） |
| 拾光（影像时间轴） | **档案 → 影像**：按年份的成片 | Document + Photo | 年份 / 类别 |
| 战队历程 | **活动**：即将开始 / 往期，含出片数与关联作品 | Event + Registration | 活动详情 |
| 加入我们 + 常见问题 | **加入**：对象/时间/地点 + 表单 + FAQ | JoinApplication（待建） | 单页，不再分叉 |
| 站点导航 | **不做** | — | — |
| 留言墙 | **不做**（讨论附在作品/活动下） | Comment | — |

导航最终 6 项：首页 / 作品 / 活动 / 成员 / 档案 / 加入。没有"关于"——协会介绍放在首页第一屏和成员页顶部，联系方式放页脚与加入页。**少一个一级栏目，就少一层套娃。**

## 四、原型做了七个决定

1. **主体从"作品"换成"协会"。** 首页先回答"我们是谁"，再给照片；数字条只用库里算得出来的：6 组作品、6 张照片、3 场活动、1 份档案。不写"成员 200+、获奖 50 项"。
2. **印样（contact sheet）作为版式母题。** 每格有编号（2026-01）、白边、图注条；本期选中的一张用红笔圈出。这是摄影独有的视觉语法，换成别的社团就不成立。
3. **照片保留原比例。** 外框统一 4:3，图在其中按原比例呈现，不裁剪。构图归拍摄者。
4. **活动按"未来最近优先"。** 往期单独一节。每场写清报名状态、名额、出片数（待接入）。修掉现有站"最近活动排最后"的问题。
5. **档案允许缺页。** 2025、2024 直接写"待归档"，并说明该放什么。不假装完整，比补一堆空文件更可信。
6. **详情页有"技术签条"。** 机身、镜头、焦距、光圈、快门、ISO、地点、授权。没有的字段留空，不编造。这是摄影站该有的深度。
7. **招新是一等公民。** 独立页 + 表单 + FAQ + 联系方式。这是社团一年最重要的一次转化，不该藏在"关于"页的一个锚点里。

另外：页头去掉了搜索与成员中心（原型未实现，避免死链接）。正式版保留，位置在导航右侧。

## 五、视觉系统

| 项 | 值 | 理由 |
| --- | --- | --- |
| 纸白 | `#F7F5F0` | 比纯白暖一点，接近相纸；照片不刺眼 |
| 墨 | `#171613` | 正文与按钮，不用纯黑 |
| 次级 | `#5F5B52` | 在纸白上对比度约 6.2:1 |
| 细线 | `#DAD4C7` | 只做分隔，不做卡片阴影 |
| 暗房红 | `#B33A2B` | 只用于编号、圈选、链接下划线；面积 < 5% |
| 字体 | 系统无衬线 + 等宽标签 | 不依赖网络字体；等宽数字做编号与参数，避免"杂志宋体"的通用感 |
| 字号 | h1 40–68 / h2 28–38 / 正文 16 / 辅文 13 / 标签 11 | 辅文不再低于 11px |
| 栅格 | 内容 1240，边距 40（手机 20），三列印样 | 与 Ultra 的 1280 接近，但更紧 |
| 圆角 | 按钮 2px，其余 0 | 照片和线框是直角，控件才有一点圆 |
| 动效 | 入场 450ms 位移 10px；无滚动劫持 | 尊重 `prefers-reduced-motion` |

**为什么不用上一版的纸白 + 杉绿 + 宋体：** 那套语言本身不差，但它把"摄影"表达成了"文艺刊物"，任何社团换上自己的名字都成立。这一版让界面退成框架（无衬线、细线、编号），把情绪全部交给照片和红笔圈选。

## 六、与旧版逐条对照

| 旧版问题 | 原型处理 |
| --- | --- |
| 首页四段同构（副标题 + 大标题 + 箭头 + 列表） | 五段结构各不相同：数字条 / 印样 / 活动列表 / 深色档案 / 双栏招新 |
| 文案抽象，没有具体的人、地点、时间 | 标题短句，正文给数字、时间、规则；成员由本人写一句 |
| 所有照片裁成 4:3 / 3:4 | 外框统一，内图保比例 |
| 只有绿色一个行动色 | 墨色按钮；红色只做标记，不承担主操作 |
| "关于"页塞了介绍 + 成员 + 招新 + FAQ | 拆到首页 / 成员 / 加入，各自单一职责 |
| 近期活动把最远的排最前 | 最近优先，往期分开 |
| 已发布资料不能加版本 | 原型表达为"版本 + 待归档"，实现时改后端 |
| 详情页居中博客结构，与列表断裂 | 详情页沿用左对齐 + 编号 + 技术签条 |

## 七、还没做 / 需要拍板

- **真实素材**：Logo、8–12 张有人脸的活动照、3 位成员的一句话、最近一次活动的时间地点人数、招新时间与 QQ 群/邮箱。没有这些，任何版式都还是示例。
- **原型未覆盖**：搜索、成员登录、作品多图浏览、评论、报名状态流转。这些在现有 Next.js 里已有实现，移植时保留。
- **数字条的数据源**：必须来自数据库实时统计（Collection / Photo / Event / Document 计数），不能手写。
- **加入表单**：需要新增 `JoinApplication` 模型、API、后台待审列表；这是现有工程没有的。
- **方向确认后再动 Next.js**：原型是静态 HTML，只用来判断结构与气质；确认后再移植，避免把可用的工程改成半新半旧的第四版。

## 八、怎么看、怎么改

```text
design/prototype/
  index.html     首页
  works.html     作品
  work.html      作品详情
  events.html    活动
  members.html   成员
  archive.html   档案
  join.html      加入
  style.css      全部样式
  build.py       生成脚本（改文案/数据后重跑）
  assets/        示例图（来自 demo-assets，已压缩）
```

重新生成：`python build.py`（在 `design/prototype/` 下）。
改文案：`build.py` 里的 `WORKS`、`EVENTS` 与各 `*_body`。
